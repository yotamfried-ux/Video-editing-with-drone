# Annotation Studio — צפייה ותיוג של הסרטונים שכבר בענן (מדריך מהיר)

המטרה: לפתוח את הסטודיו בדפדפן, לראות את סרטוני SportReel שכבר ב-Cloudflare R2, לצפות בהם, לתייג ולשמור Ground Truth — **בלי להעלות מחדש ובלי שהסטודיו יוכל לכתוב או למחוק משהו בענן**.
הכול רץ **על המחשב שלך**. אין פריסה ל-Vercel, אין שירות בתשלום, אין תשתית חדשה.

## מה צריך (חד-פעמי, ~10 דקות)

### 1. טוקן R2 לקריאה בלבד  ← **פעולה ידנית שלך** (חינם)
Cloudflare Dashboard → **R2** → **Manage API tokens** → **Create API token**:
* **Permissions: Object Read only**
* **Specify bucket(s): `sportreel`** (רק הבאקט הזה)
* שמור את `Access Key ID`, `Secret Access Key` ואת `Account ID`.

טוקן "קריאה בלבד" אינו יכול לכתוב או למחוק — גם באג בסטודיו לא יכול לפגוע בסרטוני המקור. **אל תשתמש בטוקן של הפייפליין.**

### 2. (מומלץ) קובץ רשומות ההעלאה
Supabase → SQL editor, הרץ ושמור כ-CSV/JSON (מ"Download"):
```sql
select id, status, storage_key, source_filename, source_size_bytes, verified_size_bytes,
       content_sha256, created_at, batch_id
from public.source_uploads
where status in ('verified','superseded');
```
הקובץ נותן לסטודיו SHA-256, תאריך העלאה ואצווה ללא חישוב. **בלי הקובץ הכול עובד** — הסטודיו מחשב SHA-256 מהבייטים בפעם הראשונה שפותחים סרטון.

### 3. קובץ הגדרות
```bash
cd annotation-studio
cp cloud.env.example .studio-cloud.env      # הקובץ מוחרג מ-git
# ערוך את .studio-cloud.env: STUDIO_HOME, STUDIO_CLOUD_R2_* (+ STUDIO_CLOUD_METADATA)
```

### 4. הפעלה
```bash
npm run start:cloud
# מדפיס:  open: http://127.0.0.1:4173/?t=<token>   ← פתח את הכתובת הזו בדפדפן
```
דרישות: Node ≥ 22.13 ו-`ffmpeg`/`ffprobe` מותקנים. אין `npm install`.

## שימוש
1. לשונית **ענן** → **סנכרן קטלוג מהענן**: טבלה עם שם, תאריך העלאה, גודל, ענף, מצב פייפליין (חדש / עובד), מיקום וזמינות (`raw/` / רק `processed/` / חסר), מצב זהות ותיוג.
2. **פתח לתיוג**: הסטודיו קורא את הסרטון מהענן בטווחים (Range) — אין הורדה מלאה מראש; נבנית תמונה ממוזערת, ועותק תיוג מדויק לפריימים נוצר **מקומית** (ב-`STUDIO_HOME/cache`, לא בענן).
3. צפייה, קפיצה בין פריימים, סימון ספורטאים, אירועים וקופסאות — כמו בסרטונים מקומיים. שמירה אוטומטית ב-SQLite המקומי, ניתן לסגור ולחזור.
4. **אישור Ground Truth** דורש **אימות זהות**: כפתור "אמת זהות (SHA-256)" קורא את הסרטון בזרימה ומשווה ל-SHA-256 ברשומה הקבועה. אי-התאמה = חסימה.

## מה הסטודיו לא עושה (בכוונה)
* לא כותב, לא מוחק, לא מעביר ולא מעלה מחדש אובייקטים בענן (רק GET/HEAD; נבדק אוטומטית על שרת S3 מדומה).
* לא חושף מפתחות לדפדפן; הווידאו עובר דרך נתיב מאומת מקומי.
* לא מעתיק את הסרטונים לדיסק (למעט העותק המקומי הקטן לתיוג) — **ולכן גיבוי הסרטונים עצמם נשאר באחריות ה-R2** (ראה `raw-recovery/STAGE1-REPORT.md`).

## פתרון תקלות
| סימפטום | פתרון |
|---|---|
| "החיבור לענן אינו מוגדר" | הפעל עם `npm run start:cloud` ומלא את `.studio-cloud.env` |
| `cloud storage GET returned 403` | הטוקן לא מכסה את הבאקט / לא תקף — צור מחדש |
| סרטון מופיע "רק ב-processed/" | המקור הועבר ע"י גרסה ישנה של הפייפליין; ראה `raw-recovery` (שחזור בהעתקה בלבד באישורך). אפשר לתייג גם ממנו |
| סרטון "חסר בענן" | יש רשומה אך לא נמצא אובייקט (נבדקו כל המיקומים); לא ממציאים שחזור |
| "זהות לא אומתה" | לחץ "אמת זהות (SHA-256)" |
| הסרטון לא קופץ לפריים מדויק | ממתין "מכין עותק תיוג מדויק…"; אחרי שהסתיים רענן |
