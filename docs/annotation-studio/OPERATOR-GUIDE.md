# SportReel Annotation Studio — מדריך הפעלה מקומי (Local First)

**מצב עדכני (2026-11-02, עודכן בענף ההסמכה):** Annotation Studio רץ מקומית על המחשב (Local First) עם מסד SQLite וטיוטות/גרסאות Ground Truth מקומיות; **אפשר לצפות ולתייג גם את הסרטונים הקיימים ב-Cloudflare R2 בחיבור קריאה בלבד** בלי להעלות אותם מחדש. אין כאן פריסה של ממשק הסטודיו לענן או שירות חדש בתשלום. ההסמכה המלאה לעבודה עם תיוגים אמיתיים עדיין מתועדת ב-[אפיון §22](../specs/ground-truth-annotation-studio.md#22-current-implementation-and-qualification-ledger--2026-11-02-living-status-not-a-release-claim).

## 1. דרישות
| דרישה | בדיקה |
|---|---|
| Node.js ‏22.13 ומעלה | `node --version` |
| ‏ffmpeg ו-ffprobe | `ffmpeg -version` |
| דפדפן מודרני (Chrome / Edge / Firefox) | — |

אין `npm install` — השרת ללא תלויות. (`pg` ו-R2 הם אופציונליים ולא נדרשים.)

## 2. הפעלה ראשונה
```bash
git clone https://github.com/yotamfried-ux/Video-editing-with-drone.git
cd Video-editing-with-drone/annotation-studio

# 1. תיקיית הנתונים של הסטודיו (מסד, ארכיון מקורות, מטמון). כל מצב השרת נמצא רק בה.
#    (ברירת מחדל אם לא הוגדר: ~/.sportreel-annotation-studio)
export STUDIO_HOME="$HOME/sportreel-studio"

# 2. תיקיות הסרטונים שברצונך לקטלג (נתיב:קידומת, מופרדות בפסיק). הקבצים לעולם לא משתנים ולא נמחקים.
export STUDIO_RECONCILE_ROOTS="/path/to/raw:raw/,/path/to/more:raw/"

npm start
```
השרת מדפיס כתובת חד-פעמית כגון `http://127.0.0.1:4173/?t=…` — פתח אותה. הטוקן נשמר ב-`$STUDIO_HOME/token`; בהפעלות הבאות הכתובת זהה.
בדיקת הכרות ללא נתונים אמיתיים: `npm run seed` ואז `STUDIO_HOME=.demo-home STUDIO_TOKEN=demo-token npm start` (סרטונים סינתטיים בלבד).

> הסטודיו מאזין **רק** ל-`127.0.0.1`, דורש טוקן לכל בקשה, ובודק Host ו-Origin. אין לחשוף אותו לרשת.

## 3. זרימת עבודה
1. **ספרייה → "סנכרון קליטה"**: קולט סרטונים חדשים לפי SHA-256 (זהות קבועה, לא תלויה בשם/נתיב). עותק זהה בבתים נרשם כהופעה נוספת ולא כסרטון נוסף. תיקיות `review/ approved/ previews/ pending_payment/` נדחות (אלו פלטים שנוצרו, לא מקורות).
2. **סיווג ענף**: כל סרטון חדש הוא **"לא מסווג"** (לא מניחים גלישה). סנן "לא מסווג" → בחר ענף → "שייך N מוצגים". אפשר גם לשנות ענף בתוך מסך הסימון (בורר "ענף" בסרגל העליון).
3. **גולשים**: מסך "גולשים" → הוסף גולש; בסימון בחר אותו במקש `1`–`9`.
4. **סימון אירועים**: `I` תחילת מקטע, `O` סוף; סוג האירוע נבחר מרשימת הענף; `B` לציור תיבות תיחום; `E`/`X`/`U` החלטה כלול/החרג/לא בטוח; שמירה אוטומטית (הכרטיס "נשמר" בסרגל העליון).
5. **אישור**: "אשר גרסה" יוצר גרסה בלתי ניתנת לשינוי. פריטים לא פתורים דורשים אישור מפורש.
6. **דאטהסט והערכה**: "דאטהסטים" מקפיא גרסאות מאושרות; "הערכות AI" משווה תחזיות פייפליין ל-GT, בדוח מופרד לפי ענף.
7. **ייבוא מהפייפליין**: `node scripts/gt-import.mjs predictions predictions.v1.json` ו-`node scripts/gt-import.mjs edl EDL.json --output reel.mp4` (או "ייבוא תחזיות" במסך ההערכות).
8. **הגדרות ענפים**: ענפים וסוגי אירועים חדשים נוספים במסך "הגדרות ענפים" ללא שינוי קוד.

## 4. להמשיך עבודה אחרי סגירה
סגור את הטרמינל ופתח שוב עם אותו `STUDIO_HOME` — הטיוטות, הגרסאות המאושרות, הגולשים והענפים נשמרים (נבדק אוטומטית: `tests/e2e/workflow.mjs`, תרחיש 8). טיוטה שלא נשמרה בשל ניתוק נשמרת מקומית בדפדפן ומשוחזרת.

## 5. גיבוי מוצפן בהתקן פיזי נפרד (חובה)
גיבוי באותו דיסק של הנתונים **אינו גיבוי**. הכלי מסרב ליעד באותו התקן (`BACKUP_SAME_DEVICE`) ולמחיצה אחרת על **אותו דיסק פיזי** כשניתן לזהות זאת (`BACKUP_SAME_DISK`; ב-Windows דרך `Get-Partition`). כשאין אפשרות לזהות דיסק פיזי, הדו"ח מציין `device_check: volume_only`, כלומר נבדק רק שהכרך שונה.

**כל מה שנכתב לדיסק הגיבוי מוצפן** (גרסה `gt-offsite/v2`): יצוא מסד הנתונים, צילום ה-SQLite וקובצי הווידאו עוברים AES-256-GCM, עם מפתח שנגזר ב-scrypt ו-salt/IV חדשים לכל קובץ. שמות הקבצים ביעד אינם חושפים את ה-hash של הסרטונים, והמפתח לעולם לא נכתב לדיסק. כל קובץ מפוענח ונבדק מחדש לפני שהגיבוי מתקבל. גיבוי ללא מפתח נדחה (`BACKUP_ENCRYPTION_REQUIRED`), אלא אם הצהרת במפורש שהדיסק כולו מוצפן (`--plaintext-device-encrypted`). ההצהרה נרשמת במניפסט וביומן.

**Windows — הגדרה חד-פעמית:**
1. צור קובץ מפתח על הדיסק שלך (לא על דיסק הגיבוי ולא בריפו), למשל `%USERPROFILE%\.sportreel-backup-key.txt`, עם משפט סיסמה של 12 תווים לפחות. **שמור את המשפט גם במנהל סיסמאות**: בלעדיו אי אפשר לשחזר.
2. חבר דיסק חיצוני (למשל `E:`) והרץ מתוך `annotation-studio`:
   ```powershell
   node scripts\gt-offsite-backup.mjs run    --to E:\sportreel-gt --key-file "$env:USERPROFILE\.sportreel-backup-key.txt"
   node scripts\gt-offsite-backup.mjs verify --to E:\sportreel-gt --key-file "$env:USERPROFILE\.sportreel-backup-key.txt"
   ```
3. תזמון יומי (Task Scheduler, ללא הרשאות מנהל):
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install-backup-schedule.ps1 -To "E:\sportreel-gt" -KeyFile "$env:USERPROFILE\.sportreel-backup-key.txt" -At 21:00
   schtasks /Run /TN "SportReel GT Backup"
   ```
   היומן נכתב ל-`%LOCALAPPDATA%\SportReel\backup.log`. ההתקנה מסרבת ליעד על כונן המערכת או על אותו דיסק פיזי.
4. **תרגיל שחזור** (פעם בחודש ולפני שדרוג), תמיד אל תיקייה ריקה ונפרדת:
   ```powershell
   $env:STUDIO_HOME="$env:TEMP\restore-drill"; node scripts\gt-offsite-backup.mjs restore --to E:\sportreel-gt --key-file "$env:USERPROFILE\.sportreel-backup-key.txt"
   ```
* מפתח שגוי: `BACKUP_KEY_WRONG`. קובץ ששונה או נפגם: `BACKUP_UNVERIFIED`. בשני המקרים לא משוחזר כלום (אין שחזור חלקי). הרצה חוזרת עם מפתח אחר לאותו יעד נדחית (`BACKUP_KEY_MISMATCH`).
* הרצה חוזרת בטוחה: מעתיקה רק מה שחסר ומתקנת עותק פגום ביעד מתוך המקור המאומת. היא **לעולם לא מוחקת** ביעד.
* באנר אדום בספרייה מופיע כשאין גיבוי, כשהגיבוי התקין האחרון ישן מ-7 ימים, **וגם כשההרצה האחרונה נכשלה**.
* גיבויים ישנים מגרסה v1 (לא מוצפנים) נשארים קריאים לשחזור. `verify` מתריע `plaintext_artifacts_present` כשנמצאים ביעד קבצים לא מוצפנים. הכלי לא מוחק אותם; מחיקה היא החלטה שלך.

## 6. הודעות שגיאה נפוצות
| הודעה / קוד | משמעות | מה לעשות |
|---|---|---|
| אין הרשאה (401) | נפתח בלי הטוקן | פתח דרך הכתובת שהודפסה (`?t=…`) |
| `BACKUP_SAME_DEVICE` | יעד הגיבוי על אותו דיסק | חבר התקן אחר |
| `BACKUP_SAME_DISK` | מחיצה אחרת על אותו דיסק פיזי | חבר דיסק פיזי אחר |
| `BACKUP_ENCRYPTION_REQUIRED` / `BACKUP_KEY_WEAK` | גיבוי בלי מפתח / מפתח קצר | `--key-file` עם משפט של 12 תווים לפחות |
| `BACKUP_KEY_WRONG` / `BACKUP_KEY_MISMATCH` | מפתח שגוי / מפתח שונה ליעד קיים | השתמש במפתח המקורי (ממנהל הסיסמאות) |
| `REASSIGN_CONFIRMATION_REQUIRED` | הסרטון כבר משויך לגולש אחר | אשר במפורש את שינוי השיוך |
| `BOX_NOT_AT_FRAME` / `STALE_BOX_VERIFICATION` / `BOX_IDENTITY_MISMATCH` | ניסיון לאמת BOX שלא קיים בפריים, שהשתנה, או של מבצע אחר | צייר/תקן BOX בפריים, בחר מבצע ואמת מחדש |
| `BLOCKING_ITEMS` | BOX סומן "גולש שגוי" במקטע | תקן ואמת, או החרג את המקטע |
| הטיוטה עודכנה במקום אחר (409) | פתוח בשני חלונות | טען מחדש ובדוק מה השתנה |
| סוג האירוע אינו תואם לענף | אירוע מענף אחר | בחר סוג אירוע של הענף או שנה ענף למקטע |
| לשינוי הענף יש מקטעים לא תואמים | מקטעים עם אירועים שלא קיימים בענף החדש | מפה אירועים בחלון שנפתח; שום מקטע לא נמחק |
| ארכיון המקור לא אומת | ה-hash של הקובץ בארכיון לא תואם | "אמת ארכיון"; שחזר מהגיבוי; הקובץ המקורי לא נמחק |
| רשומה בלתי ניתנת לשינוי | ניסיון לשנות גרסה מאושרת/דאטהסט/יומן | מכוון — צור גרסה חדשה |

## 7. מה אין (בכוונה)
* אין מחיקה של סרטונים, גרסאות או דאטהסטים — לא ב-API ולא ב-DB (טריגרים). 
* אין גישה של הפייפליין ל-Ground Truth; הפייפליין מקבל רק זהות סרטון (sha256, גודל, שם) דרך manifest עיוור.
* יש **חיבור R2 אופציונלי לקריאה בלבד** כאשר מוגדר טוקן Object Read only. הסרטונים נצפים דרך השרת המקומי; SQLite ממשיך להחזיק את תיוגי ה-Ground Truth. PostgreSQL הוא backend אפשרי אך אינו נדרש להפעלה המקומית. ראו [CLOUD-QUICKSTART](CLOUD-QUICKSTART.md).

## 8. Troubleshooting
* `node: --experimental-sqlite` / גרסה ישנה: ודא Node ≥ 22.13.
* סרטון לא מתנגן: הדפדפן אינו תומך בקודק המקורי — הסטודיו מייצר proxy אוטומטית בעת הקליטה; הרץ "סנכרון קליטה" שוב.
* הדיסק התמלא: הארכיון (`$STUDIO_HOME/archive`) הוא עותק מלא של המקורות; ראה סעיף 5 לפני העברה או ניקוי.


## 9. עבודת קטלוג V2 — מה כל מצב אומר (2026-11-02)

**הפעלה ב-Windows עם R2:** בתוך `annotation-studio`, לחיצה כפולה על `start-studio-cloud.cmd` (ראו [CLOUD-QUICKSTART](CLOUD-QUICKSTART.md)). אסור לשתף את כתובת `?t=` או את `.studio-cloud.env`. החיבור ל-R2 הוא GET/HEAD בלבד: הקוד מסרב לכל פעולה אחרת.

**תהליך עבודה:**
1. ספרייה או ענן → **שייך לגולש** → בחר גולש קיים או צור חדש → שמור. השיוך נשמר גם בלי אף אירוע, והסרטון מופיע מיד ב"גולשים" → הגולש → "סרטונים משויכים".
2. שינוי שיוך קיים מחייב אישור מפורש. כל שינוי נרשם בהיסטוריה. "ביטול" נעשה בשיוך חוזר, וההיסטוריה לא נמחקת. שני חלונות ששומרים במקביל: אחד מצליח, השני מקבל הודעת "עודכן במקביל" ושום נתון לא נדרס.
3. Workbench: `I` ו-`O` יוצרים אירוע. אירוע חדש מתחיל **שימושיות "לא יודע עדיין"** ו**החלטת דאטהסט "לא בטוח"**, ואתה קובע את שניהם באופן אקטיבי.
4. **מי ביצע** נבחר בנפרד לכל אירוע. בעל הסרטון אינו מבצע אוטומטית.
5. BOX: `B` ואז גרירה על הגולש. **ציור אינו אימות.** בלשונית "אימות BOX" יש ארבע החלטות לפריים הנוכחי: נכון על הגולש / גולש שגוי / מוסתר או לא נראה / לא ניתן לקבוע. האימות חל **רק על הפריים הזה, רק על הגאומטריה הזו ורק על המבצע הזה**. הזזת התיבה או החלפת מבצע מבטלות אותו ("⟳ לבדיקה מחדש"), וההיסטוריה נשמרת.
6. "נקודות בדיקה נדרשות" נקבעות אוטומטית: תחילה, אמצע, סוף, שינוי תנועה, קפיצה חדה, הסתרה או יציאה מהפריים, והצטלבות עם גולש אחר. מצב המעקב מוצג כ: טרם נבדק / נבדק חלקית / אומת בטווח שנבדק / דורש תיקון / לא ניתן לקבוע. פריים בודד אף פעם אינו "מעקב מאומת".
7. "גולש שגוי" חוסם אישור עד שמתקנים או מחריגים את המקטע. פריטים פתוחים אחרים (לא בטוח, שימושיות לא נקבעה, חלקי בלי סיבה) מאפשרים אישור רק בסימון מפורש, ונרשמים כהסתייגויות בגרסה המאושרת וביומן.

**פאנל "מצב הסרטון"** מציג צירים עצמאיים, ואף אחד מהם לא מרמז על אחר: מצב עבודה · בעל הסרטון · טיוטה נשמרה (≠ אושרה) · שימושיות · החלטת דאטהסט · פריימי BOX שאומתו ידנית · כיסוי צפייה (≠ אחוז השלמה) · Ground Truth מאושר · בדאטהסט מוקפא. אפשר לסמן סרטון "דורש בדיקה" גם בלי מקטעים.

**הסמכה מול סרטוני DJI אמיתיים (לפני תיוג אמיתי ראשון):** על עותק מבודד, בלי לגעת ב-GT הקיים ובלי לכתוב ל-R2:
```powershell
node --env-file=.studio-cloud.env scripts\qualify-real-footage.mjs --evidence "$env:USERPROFILE\sportreel-qualification" `
  --case single=raw/<key>.mp4 --case multi=raw/<key>.mp4 --case crossing=raw/<key>.mp4 --case occlusion=raw/<key>.mp4 `
  --case 4k_fast=raw/<key>.mp4 --case quality_issue=raw/<key>.mp4 --case no_events=raw/<key>.mp4 --probe-delete-permission
```
הסקריפט בודק אוטומטית: זהות SHA-256 מהבתים, שיוך בלי אירוע, הפעלה מחדש, ברירות מחדל, דחיית אימות עוין, ביטול אימות בשינוי גאומטריה, חסימת אישור, ומיפוי פריים proxy↔מקור לפי דמיון פיקסלים. הוא גם מוודא שהטוקן לא יכול למחוק: הוא שולח DELETE למפתח אקראי שלא קיים, כך ששום נתון לא משתנה. הוא שומר פריימים לבדיקה ידנית **מחוץ לריפו**. פריטים שמסומנים `HUMAN` נשארים `NOT_TESTED` עד שתבדוק אותם בממשק.

**מוכנות:** ההחלטה `CATALOG_GO` / `NO-GO` מופיעה ב-[CATALOG-READINESS](qualification/CATALOG-READINESS.md). אל תאשר את התיוג האמיתי הראשון לפני שקראת אותה.
