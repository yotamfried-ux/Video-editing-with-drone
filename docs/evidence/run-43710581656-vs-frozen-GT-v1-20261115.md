## Method and limitations

We matched source media by source SHA-256, reconstructed each EDL shot's source window using original FPS (~59.94), src_start frame, output span and EDL speed, then intersected with the frozen revision's approved GT segment intervals, labels and athlete IDs. Results are approximate where crossfades or frame rounding occur (typically sub-second); they measure **time-window overlap**, not semantic completeness, bbox accuracy or actual rendered pixels. Bbox and motion fidelity were NOT visually assessed.

The GT schema contains **45 labeled segments**: **42 include** and **3 exclude**, across 24 source videos. Some included segments are maneuvers or wipeouts within one surf ride; **do not mistake 42 segments for 42 separate rides**. There are **13 distinct athlete identities with included actions** in frozen GT-v1. These IDs are annotation identities, not app-user biometric IDs.

On the completed run: 14 output EDLs / 25 shots; 14 REVIEW drafts; **10 marked publishable, 4 withheld**. Final QA was 12 PASS / 2 FAIL, but two PASS drafts were independently withheld by primary-actor policy. GitHub Actions reports success while run_quality_report.status is fail and the business gate reports outcome=partial (published 10 of 14 pipeline-designated athletes).

Aggregate temporal audit:

- 299.65 seconds labeled include in frozen GT; approximately **270.90 seconds overlapped by EDL windows** (90.4% time overlap; 28.75 seconds not overlapped). Not a formal event recall score; not directly comparable to earlier run's 88% catalog seconds metric without harmonizing definitions.
- 16.67 seconds labeled exclude in frozen GT; **16.23 seconds overlapped by EDL windows** spread across all three excluded intervals. This is a high-priority evidence contradiction, not a proof that every visible frame is unacceptable.
- **25/25 EDL shots have missing/null event_id**, although source hash, track ID and local athlete reference exist. Therefore a shot cannot currently be joined directly and unambiguously to a stable, source-scoped candidate event.
- Independent source/identity correspondence yields **one likely false merge, one false split, and a spurious all-excluded-source reel**. These three errors make a simple total-draft count misleading: 14 drafts versus 13 included GT identities is not a reliable correctness metric.

- **0094** first-athlete 2.0–22.5s: bound primary track frame continuity approximately **0.367**; competing active tracks in frame; QA withheld.
- **0140** as a shot in 0112's athlete reel 1.4–11.43s: primary track continuity **0.409**, concurrent people and missing target frames; QA withheld.

These are **window-specific** continuity measurements, not tracking HOTA/IDF1 scores. The aggregate 101 short tracks out of 278 detected tracks in the run is a fragmentation clue, not proof that 36% of the *primary-actor trajectories* are wrong.

For run #43710581656, only 10/14 reels were publishable, four QA tasks persisted, final QA **two FAIL, two PASS-but-blocked**. ## Annotation ground-truth provenance risk

Frozen dataset includes **3,174 bbox keyframes** over 24 sources; **3,173 marked verified_correct**, **3,083 with origin=suggested**, **91 with origin=manual**, **all 3,174 missing verified_at and verified_by**. This is an audit-trail deficiency, **not evidence that all boxes are wrong**. Bulk approval may be an intentional semantics; preserve original immutable approvals, add provenance rules going forward, independently adjudicate contradictory examples and never fabricate past verifier identities/timestamps. In particular, TrackEval scores cannot be treated as independent visual proof if labels were suggested by the same model being evaluated without independent review.

## Missing automatic comparison

At inspection, ground_truth.pipeline_predictions, ground_truth.edl_records and ground_truth.evaluation_runs each had **0 rows**, despite predictions/v1 and EDL exports being available in GitHub's diagnostics ZIP. This establishes an unclosed **evaluation feedback loop**. Never expose GT to the inference pipeline; run a separate, read-only, post-run evaluator on frozen SHA/revision IDs.

## What cannot be verified here

No MP4 pixels from the private R2 review objects were directly accessible; there is no visual adjudication of 0152 board color, actor overlays, bbox correctness, edit smoothness, source timestamps in images or "viral" output quality. The report is a structured source-to-output comparison. Obtain authorized **private compressed proxies** from the existing sportreel R2 bucket and a human reviewer before changing ground-truth labels or enabling new editing/identity defaults.

## Reproduce the evidence

1. Read GT-v1's dataset_members joined to their frozen annotation_revisions, sources and athletes in project bcndgmymnismbxvdeetc (read only). Extract source SHA, FPS, per-segment decisions and athlete IDs.
2. Download artifact #14162886161 of GitHub Actions run #43710581656; read predictions.v1.json, 14 edl/*.edl.json, publishable_reel_manifest.json and run_quality_report.json.
3. Match source_sha256, compute shot source start/end from src_start and original FPS, map to EDL output frames via per-shot speed and output FPS; use unioned intervals and avoid double counting transitions.
4. Join each GT segment by source SHA and window. Distinguish include, exclude and multiple GT athletes in one source; build an athlete-level bipartite identity map across sources. The pipeline's numeric tracker ID is **source-local**, never a cross-video identity.
5. Keep separate counts for **source-time overlap, event completeness, clip-to-athlete purity, QA blocking, and final publishability**. They must not be collapsed into one "engagement" or "coverage" score.
6. Re-evaluate the newer run separately once completed, with exact commit/run/artifact IDs, without mixing baselines.
